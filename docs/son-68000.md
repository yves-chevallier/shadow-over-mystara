# Son : côté 68000

Le 68000 ne produit aucun son : il envoie des **commandes** au programme Z80 (qui pilote le QSound)
par la RAM partagée 0x618000-0x619fff. Ce document décrit le format des commandes et la file qui les
transporte. Code Rust : `port/ddsom-game/src/sound.rs` (+ `sound_table.rs`, généré par
`tools/gen_sound_wrappers.py /home/ycr/som/listing.txt /home/ycr/som/prog_dec.bin port/target/release/examples/dis
/home/ycr/som/rom`). Le programme Z80 est décrit ailleurs.

## Vue d'ensemble

```
code du jeu --jsr--> wrapper « sfx » --> enfileur 0xe0836 / 0xe0848 --> file circulaire (RAM 68000)
                                                                                 |
VBLANK 0x574 --bsr--> 0x68c : une entrée de la file -> octets 0x618001... -> Z80 (acquittement 0x61801f)
```

## La file de commandes

64 entrées de 16 octets en `A5-0x5aa4` (= 0xFF255C-0xFF295B). Deux têtes (mots, multiples de 0x10,
masque 0x3f0) juste après la file :

| Adresse | Rôle |
|---|---|
| `A5-0x56a4` (0xFF295C) | tête de lecture : prochaine entrée à transmettre (0x68c) |
| `A5-0x56a2` (0xFF295E) | tête d'écriture : prochaine case libre (0xe0848) |
| `A5-0x56a0` (0xFF2960) | alternance 0 / 0xFFFF des wrappers à deux variantes (0xedee4) |

La file est pleine quand `(lecture - 0x10) & 0x3f0 == écriture` (une case reste libre). Une commande
envoyée à une file pleine est perdue (retenue C levée au retour de 0xe0848).

**Entrée** : trois longs `D1`, `D2`, `D3` (12 octets utiles, 4 de remplissage), tels que les wrappers
les composent :

| Octet de l'entrée | Champ | Vers l'adresse Z80 | Rôle |
|---|---|---|---|
| 0 | D1 bits 24-31 | 0x618007 | (mot haut de D1, voir 0xe0a2e) |
| 1 | D1 bits 16-23 | 0x618009 | |
| 2 | D1 bits 8-15 | 0x618001 | **numéro de commande**, octet haut |
| 3 | D1 bits 0-7 | 0x618003 | **numéro de commande**, octet bas |
| 4 | D2 bits 24-31 | (non transmis) | |
| 5 | D2 bits 16-23 | 0x61800d | paramètre |
| 6 | D2 bits 8-15 | 0x61800f | **panoramique** pour les wrappers qui en calculent un |
| 7 | D2 bits 0-7 | 0x618011 | paramètre |
| 8-11 | D3 bits 24 à 0 | 0x618013, 15, 17, 19 | paramètres (ex. 0x00500000 : octet 9 = 0x50) |

Les octets de la RAM partagée sont aux adresses impaires (bus 8 bits du Z80 sur le bus 16 bits).

## Transmission au Z80 (0x68c, chaque VBLANK)

1. `0x619ffd` ← 0xFF si `A5+0x28 != 0`, sinon 0 (verrou de sortie son lu par le Z80).
2. Le compte à rebours `A5+0x7fc2` (mot) est décrémenté s'il est non nul (délai posé par les
   commandes 0xff06/0xff07 de 0xe0a40-0xe0a82 ; table de (délai, durée) en 0xe0ab0).
3. Si la file n'est pas vide **et** `0x61801f == 0xFF` (le Z80 a lu la précédente) : les 11 octets
   ci-dessus sont copiés, `0x61801f` ← 0 (nouvelle commande disponible), la tête de lecture avance.
   **Une seule commande par image.**
4. Saut vers 0xedf80 : affichage des verrous `0x61800x` pour le menu test (sans effet hors test).

La routine native `son_envoyer_z80` (touches_sound) fait 1-4 (l'affichage des verrous est réécrit : `afficher_verrous`).

## Les enfileurs

* `0xe0848` : enfile D1, D2, D3 ; C levé si la file est pleine. Sortie : D0 = nouvelle tête
  d'écriture (ou `(lecture-0x10)&0x3f0` si pleine), A1 = fin de l'écriture.
* `0xe0836` : idem si le son est autorisé : `A5+0x7fcc != 0` (mot) **ou** `A5+0x30 != 0` **ou**
  `A5+0x27 != 0` (octets) ; sinon rien n'est émis (C levé, X N Z V à 0).
* `0xe0882` (commande 0xff00), `0xe0a10` (0xff05), `0xe0a2e`/`0xe0a40`/`0xe0a70`/`0xe0a82`
  (0xff06/0xff07, avec délai) : commandes de service, enfilées sans test d'autorisation, registres rendus
  (sauvegarde sur la pile du 68000). Les commandes à délai écrivent d'abord le verrou `0x618005` (D1.b pour
  0xe0a2e et 0xe0a70, 0xff pour 0xe0a40, 0 pour 0xe0a82 : `touches_sound`), puis lisent en clair, à l'indice
  D0.w de la table 0xe0ab0, le délai (`A5+0x7fc2`) et le mot haut de D1. Natives `son_service_*` de `sound.rs`.
* `0xe2240`, `0xe22e8` : bruit du personnage (wrappers 0xe2248, 0xe22f0), ou 0xe2390 dans la version à palette
  alternative (`A5+0x70`) ; `0xee044` : pile privée vide (pointeur = sa propre adresse).

## Les wrappers `sfx_*` (0xe0be2-0xede08)

Chaque wrapper : empile D0-D7/A0-A4 sur une **pile privée** (pointeur en `A5-0x55e6` = 0xFF2A1A, qui
grandit vers le bas ; initialisée par 0xee044), met D0-D3 à zéro, compose D1/D2/D3, appelle un enfileur
et dépile. **Tous les registres sont rendus intacts** (seule la mémoire change : la file, et la copie
morte des registres sous le pointeur de pile privée — reproduite par la version native). 517 points
d'entrée (repérés par les octets de leur prologue), dont 504 suivent un des schémas suivants et sont décrits par
`WRAPPERS`. Le générateur lit le listing et, pour les 75 wrappers tombés dans ses trous ou ses désalignements,
désassemble par `examples/dis` (instructions traduites dans la syntaxe du listing) :

| Élément du schéma | Effet |
|---|---|
| commande constante | `D1 = n` (mot) |
| `Memo` | `D1` = dernière commande gardée (`A5+0x7fc4`), rejouée (0xe12f4) |
| `DuD4` | `D1` = D4.w de l'appelant (musiques 0xe17a4, avec `MEMO`, et 0xe17e2) |
| `Alternee(table)` | appelle 0xedee4 : D1 = 0 puis 2 à tour de rôle (mot `A5-0x56a0` basculé) ; `D1 = table[D1]` : deux variantes de la commande |
| `ParObjet(table)` | appelle 0xedef2 : indice = `2 × A0[2] + ((A0[3] & 0xe) << 2)` ; `D1 = table[indice]` (octet 2 : numéro de joueur, octet 3 : personnage) |
| `ParOctet2(table)` | indice = `2 × A0[2]` |
| constantes `d2`, `d3` | octets de paramètres fixes |
| `PAN` | panoramique : voir ci-dessous, ajouté (OU) à l'octet 1 de D2 |
| `GARDE` | ne rien émettre si l'octet `A5-0x55e2` (0xFF2A1E) est non nul |
| `MEMO` | recopie D1 en `A5+0x7fc4` avant d'enfiler |
| `DIRECT` | appelle 0xe0848 (sans test d'autorisation du son) |

Les tables de commandes sont des mots rangés dans le code, lus par des accès relatifs au PC (donc
**en espace programme**, opcodes déchiffrés) : la version native les relit en ROM à l'exécution ;
aucune donnée de la ROM n'est copiée dans le dépôt.

**Panoramique** (A0 = objet à l'origine du bruit) :

```
ecart = A0.x(mot, +8) - camera.x      camera = A5+0x5a6, ou A5+0x5ae si A5+0x36 != 0
si ecart < 0 (signé 16 bits) : ecart = 0
si ecart >= 0x180 (non signé) : ecart = 0x178
pan = table_ROM[0xee04e + (ecart & 0x1ff) / 8]       -> 0x00 (gauche) .. 0x10 (centre) .. 0x20 (droite)
D2 |= pan << 8
```

### Les aiguillages

Les 13 autres points d'entrée (`sound::AIGUILLAGES`) ne composent pas leur commande : après la même sauvegarde
sur la pile privée (D0-D3 mis à zéro), ils choisissent dans une table un autre wrapper qu'ils appellent (il fait sa
propre sauvegarde 52 octets plus bas, avec les registres modifiés par l'aiguillage), ou enfilent une musique :

| Sorte | Entrées | Choix |
|---|---|---|
| `ParD4` | 0xe6910, 0xe7c20, 0xe7e10 | rien si D4.b < 0 ; sinon D4.w = 2 × D4.b, D0.w = mot de la table en D4, cible = table + D0 |
| `ParVariante` | 0xe7622, 0xe774c, 0xe78e8, 0xe7a12 | D1.w = mot de la table en `A0[3] & 0xe`, cible = table + D1 |
| `ParVarianteLong` | 0xe823a | A1 = long de la table en `2 × (A0[3] & 0xe)` |
| `ParVarianteEtGenre` | 0xe662a | A1 = long de la table en `2 × (A0[3] & 0xe)`, puis A1 = long **en clair** en `A1 + A0[0x47]` |
| `ParA1` | 0xec046, 0xec200 | A1 = long de la table en `4 × A1[0x44]` |
| `Musique` | 0xe0c5c, 0xe0d8c | gardé (`A5-0x55e2`) ; D1.w = mot de la table en `2 × scène` (`A5+0x34`) ; rien si D1 <= 0 (0xe0c5c) ou D1 < 0 (0xe0d8c, qui recopie le mémo avant le test) ; mémo `A5+0x7fc4` puis 0xe0836 |

Les tables (relatives au PC) se lisent en espace programme. Au retour, tous les registres sont relus sur la pile
privée comme dans l'original. La cible vide de `0xec200` (un simple `rts`, 0xec238) est la native `son_aucun`.

## Durée

La durée de chaque wrapper est exacte (au cycle près, vérifiée sur plusieurs centaines de milliers
d'appels sur états aléatoires) : le code d'origine est parcouru instruction par instruction en
suivant les décisions de branchement que la routine native prend elle-même (`sound::marche`).

## Validation

* `tools/validate_all.sh` : exerce les wrappers qu'atteignent les scénarios (une cinquantaine) et les aiguillages
  (`son_aiguillage`).
* `port/ddsom-game/examples/fuzz.rs son` : appelle **chaque** routine du son (les wrappers, les
  enfileurs, 0x68c) en mode contrôle depuis des états tirés au sort (drapeaux, file vide/pleine,
  caméras, objet A0...), l'original s'exécutant à côté ; permet de valider les chemins que les
  scénarios n'atteignent pas.
* `examples/couverture.rs` : nombre d'appels de chaque routine native sur un scénario.
